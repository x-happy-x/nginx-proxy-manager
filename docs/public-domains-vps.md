# Несколько публичных доменов и VPS

NPM-110 развивает пилот INFRA-105. В мастере сервиса список публичных адресов:
каждый адрес — отдельный маршрут со своим способом публикации. Например,
`app.crubs.crazedns.ru` через KeenDNS, `app.cdn6.ru` через один VPS и
`app.example.org` через другой работают одновременно. Дополнительные локальные
алиасы и политики доступа сохраняются при редактировании сервиса.

## Подключение сервера

Откройте **Машины → Настройка → Публичные серверы** либо блок публичных серверов
под списком сервисов в **Прокси и домены**. Укажите имя, уникальный ID до 16
символов, IP/имя VPS и SSH-порт. Автоматическая установка рассчитана на
Debian/Ubuntu с systemd и root SSH. Адрес, порт и способ подключения сохраняются
независимо для каждого сервера; поддерживается до 32 подключений.

Для первого входа используйте существующий root-ключ или пароль. Backend
установит отдельный ключ управления HomeNet и очистит введённые реквизиты из
формы после подключения. Исходный ключ и пароль в конфигурации не сохраняются.
Отпечаток SSH сначала показывается для сверки, затем закрепляется: при смене
ключа автоматическое соединение останавливается. Повторный вход использует
сохранённый отдельный ключ, без браузера и исходного пароля.

В карточке показываются состояние соединения, последние метрики сервера,
активные домены и число переподключений. Устаревшие показатели помечаются;
нагрузка — системный load average за минуту, а не процент использования CPU.

## Домены

1. Направьте публичные A/AAAA домена на выбранный VPS. Все возвращаемые адреса
   должны соответствовать адресу сервера. Wildcard DNS, например
   `*.cdn6.ru → 213.155.28.79`, позволяет добавлять новые имена без изменений
   зоны. Это не wildcard-сертификат: ACME выдаёт сертификаты для конкретных имён.
2. Добавьте полное имя в мастер сервиса, выберите сервер. Можно добавить
   несколько адресов и несколько серверов одному сервису.
3. Сохраните черновик, проверьте и примените маршруты обычным способом.
4. Дождитесь состояния **На связи** в карточке VPS. Настройка удалённого
   HTTPS выполняется фоном и может занять несколько минут. Успех применения
   локальных маршрутов сам по себе не подтверждает успех ACME или SSH.

DNS у регистратора автоматически не меняется. На VPS должны быть доступны
TCP 80/443, SSH и ACME. Установка не меняет firewall. Существующие домены и
wildcard-виртуальные хосты проверяются на конфликт; чужие конфиги не заменяются.
При слишком сложных существующих regex server_name публикация отклоняется.

HTTPS завершается на VPS. До дома трафик идёт внутри SSH, на обеих сторонах
дополнительные порты привязаны только к `127.0.0.1`. HomeNet принимает запрос
на отдельном HTTP-входе с фиксированными Host/HTTPS-признаком; сохраняются шлюз
Account, правила доступа сервиса и WebSocket. Внешний трафик отмечается как
external в журнале. Домен VPS не подменяется домашним IP в локальном DNS и
mihomo hosts: в том числе из LAN он открывается через VPS с публичным сертификатом.

## Ограниченный интернет и mihomo

В поле SOCKS укажите адрес доступного mihomo, например `127.0.0.1:7891` на
роутере. SSH настройки, мониторинга и туннеля идут через этот SOCKS. При отказе
SOCKS скрытого перехода на прямое подключение нет. Нужное исходящее правило
mihomo должно направлять **SSH-адрес и порт VPS** в работающую группу. Для
имеющегося VPS в сети уже есть правило порта 22/адреса `213.155.28.79` в «Обходы».
HomeNet не меняет выбранную группу и не перезапускает mihomo.

В режиме **Подбирать VPN при недоступном туннеле** HomeNet создаёт отдельную
selector-группу `HomeNet VPS ID` и SOCKS-вход только на loopback. Группу и вход
добавляет владеющий конфигурацией VPN-модуль через приватный контракт Core;
конфигурация проверяется `mihomo -t`, переключается с backup и reload без
перезапуска процесса. Основные группы, правила и выбранные пользователем
выходы не меняются. Для другого, внешнего SOCKS автоподбор не включается.

При потере SSH HomeNet выбирает один другой доступный прокси из этой группы.
Кандидаты берутся из недавних успешных проверок самого mihomo; массовый
healthcheck подписок не запускается. Проверка читает только SSH-баннер: без
передачи имени пользователя, ключа, клиентского SSH-баннера или авторизации.
При работающем туннеле активных проверок других VPN нет.

Ограничения общие для одного SSH-адреса/порта, включая несколько записей VPS:
не чаще одной попытки и одной banner-пробы в минуту, максимум шесть циклов за
30 минут. После исчерпания бюджета действует пауза до следующего окна.
Неудачный выход исключается на 30 минут. Бюджет хранится в приватном состоянии,
поэтому перезапуск службы, смена ID и кнопка переподключения не сбрасывают
частотные ограничения. Ошибка авторизации или отпечатка останавливает
автоматические попытки до исправления ключей и явного переподключения.
Это снижает риск блокировок; правила и ограничения чужих VPN/VPS могут
отличаться, поэтому абсолютного отсутствия блокировок обещать нельзя.

На телефоне публичные домены тоже должны идти через работающий выход mihomo,
например `DOMAIN-SUFFIX,cdn6.ru,Обходы`. Один только домен/VPS не делает адрес
доступным при белых списках: необходим работающий выход. Проверка настоящих
ограничений мобильного оператора выполняется телефоном во время ограничений.

## Восстановление, сертификаты и откат

Туннели берутся только из последнего применённого снимка, не из черновика.
Worker восстанавливает их после перезапуска HomeNet, закрывает соединения при
изменении конфигурации/отключении модуля и повторяет неуспешное подключение с
задержкой от 5 до 60 секунд. Проверка живости работает в обе стороны:
клиентский keepalive и серверные `ClientAliveInterval 15` / `ClientAliveCountMax 3`
освобождают зависшие сеансы и обратные порты после потери сети.

Ключ туннеля отдельный от ключа управления. Его системный пользователь
`homenet-tunnel-ID` не имеет shell-сеансов, допускает только reverse forwarding
на перечисленные loopback-порты. Обычный ключ управления нужен для nginx,
ACME и мониторинга; хранится только на устройстве HomeNet с режимом `0600`.

На VPS меняются только файлы с маркером владельца HomeNet:
`/etc/nginx/conf.d/homenet-public-ID.conf`,
`/etc/ssh/sshd_config.d/homenet-public-ID.conf`, ключ туннеля и hook продления.
Перед заменой сохраняется приватный журнал в
`/var/lib/homenet-public/servers/ID/transaction.json`. Ошибка восстанавливает
предыдущие файлы; прерванный журнал восстанавливается при следующей попытке.
Параллельную настройку одного ID блокирует `flock`. Внешние файлы, существующие
пользователи без маркера и занятые reverse-порты не присваиваются HomeNet.

Certbot использует HTTP-01/webroot и системный таймер продления; deploy hook
проверяет nginx и перечитывает его конфигурацию. Удаление домена и применение
маршрутов закрывает его туннель и удаляет управляемую публикацию; сертификаты
сохраняются. Отключить сервер можно после удаления его доменов из черновика и
применённой конфигурации. Учётная запись и ключ управления на удалённом сервере
автоматически не отзываются: отключение интеграции прекращает мониторинг, а
не выполняет удалённое удаление данных.

`PUBLIC_SERVERS_DIR` задаёт приватный каталог состояния, по умолчанию
`APP_DIR/.runtime/public-servers`. `servers.json` содержит подключения и
отпечатки; отдельные `ID-admin.key` и `ID-tunnel.key` содержат ключи. Каталог
включайте в приватный backup HomeNet. Он не отдаётся API или редактором конфигов.

## Проверки разработки

`cd backend; go test ./...` и `go test -tags=integration_worker ./manager`;
`go test -race ./manager -run TestPublic` проверяет живой локальный SSH fixture,
передачу данных, разрыв и повторное подключение. Python-тесты
`python -m unittest discover -s scripts/tests -p test_public_provision.py`
проверяют откат ACME, восстановление журнала, удаление только своих файлов и
конфликты DNS. `node scripts/tests/public-domains.test.mjs` проверяет смешанные
алиасы, разные VPS и сохранение политик доступа.

Для изолированного UI-стенда соберите `proxy,pve` через build-modules и задайте
`PREVIEW_PUBLIC_PROXY=fake`, `PREVIEW_PVE=fake`, `PREVIEW_MODULE_VERSION=1.6.0`;
запустите `node scripts/modular-preview.mjs proxy,pve 48659`. Это loopback-стенд
с вымышленными адресами, без подключения к домашним устройствам и VPS.
