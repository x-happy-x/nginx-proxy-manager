# ИИ через новый OLCRTC VPS

NPM-119. Целевой сервер ishosting `38.180.37.198` (Казахстан),
имя в HomeNet — `AI-38.180.37.198`. Первоначальный VPS `88.214.53.84`
не смог подключиться к площадкам связи; его диагностика сохранена ниже.
Установка выполняется штатным мастером OLCRTC: SSH-ключ HomeNet, серверная
сборка совместимой версии, systemd, подбор Jitsi и локальное UDP-реле.
Пароль SSH и ключи туннеля в репозиторий не сохраняются.

`scripts/ai-olcrtc-route.py --patch` принимает приватный JSON текущего Mihomo
и возвращает секции для HomeNet `/api/core/config/{check,apply}`. Передавать
их в `set` вместе с актуальным `sha`; сначала выполнить check. Не печатать
исходный конфиг, patch или ответы с YAML в общедоступные журналы.

- `ИИ · сервер` — ручной переключатель. Основной выбор —
  `ИИ · OLC 38.180.37.198`; доступны прежние группы и отдельные узлы подписок.
- `ИИ · OLC 38.180.37.198` автоматически выбирает только варианты этого VPS
  из файлового провайдера `olcrtc`. Страна-флаг и название Jitsi могут меняться;
  фильтр привязан к уникальному имени сервера. При пустом списке — `REJECT`.
- Все существующие правила с целью `ИИ` переводятся на `ИИ · сервер`.
  При отказе нового VPS другой сервер автоматически не выбирается.

Выбрать другой сервер можно вручную в HomeNet, VPN → группы → `ИИ · сервер`.
Для возврата выбрать `ИИ · OLC 38.180.37.198`. После первого применения явно
выставить этот выбор через API групп: сохранённый выбор из cache.db может
иметь приоритет над порядком списка. `profile.store-selected` сохраняет выбор.

Обе новые группы имеют собственные имена, которые генератор маршрутизации
HomeNet не пересоздаёт. Правила ИИ с новой целью также сохраняются при сборке
маршрутизации; изменения подписок сохраняют провайдер `olcrtc`.

Перед переключением проверить: конфигурация принята `mihomo -t` через HomeNet;
сервер и рабочие варианты видны в HomeNet; выход через новый VPS подтверждён;
HTTPS запросы к ИИ совпадают с правилами и цепочкой новой группы; работает UDP
и доступ к домашним/корпоративным сервисам. Авторизованные сессии всех
ИИ-провайдеров и их ограничения аккаунтов сетевыми пробами не проверяются.

История первоначального VPS `88.214.53.84` на 09.11.2026: OLC и UDP-реле
установлены, конфигурация прошла HomeNet check,
но рабочий туннель не получен. Все 15 стандартных площадок Jitsi проверены:
большинство недоступны напрямую с роутера; `meet.egovm.ru` не отвечает с VPS,
а `meet.riddlerx.org` возвращает 502 при подключении XMPP/BOSH. Проверка DNS
подтвердила одинаковые адреса у обеих сторон. VPS напрямую достигает API
OpenAI, Anthropic и Gemini, которые требуют авторизацию без региональной
ошибки. До получения рабочего транспорта правила ИИ не переключаются.
Пользовательская встреча Телемоста проверена через HomeNet `vp8channel`:
авторизация выдаёт данные подключения, но VPS не устанавливает TCP к
`goloom.strm.yandex.net` / `87.250.254.244:443`. Прямая проверка сокетом вне OLC
также завершается таймаутом; сайт Телемоста с VPS недоступен, `cloud-api.yandex.ru`
доступен. У роутера TCP к тому же адресу работает. DNS Google/Yandex и Google DoH
с ECS возвращают одинаковый IPv4; глобального IPv6 на VPS нет. OUTPUT имеет
политику ACCEPT, правила HomeNet запрещают только loopback/приватные сети и не
затрагивают этот публичный адрес. Переключение транспорта Телемоста не устраняет
недоступность общего узла сигнализации. Запрошена встреча WB Stream.
Страница `stream.wb.ru/login` сейчас предлагает только вход сотрудника и гостя,
обычная регистрация не показана. У пользователя создание встречи гостем
возвращает 403. WB Stream не является доступной самостоятельной заменой без
организатора с подходящей учётной записью; чужие публичные комнаты не использовать.
Не считать задачу завершённой по одному факту успешной установки.

Приватная исходная копия на роутере:
`/opt/etc/mihomo/recovery-NPM-119-20261109`. HomeNet при применении создаёт
дополнительную `.homenet-backup-*.yaml`; откат конфигурации также проводить
через HomeNet, сохраняя текущий secret контроллера.
