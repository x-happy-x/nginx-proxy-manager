# Резервирование CrazyDNS

NPM-106, продолжение NPM-13. Порядок: **DIRECT → OLCRTC → независимый VLESS**.
Правила TCP 8090 и UDP 9/4044 направляются в единую группу `CrazyDNS`.
`scripts/crazedns-failover.py` выбирает канал через контроллер Mihomo;
сам движок, Core и XKeen не перезапускаются.

Фрагменты: `config/crazedns-olcrtc.yaml` (имя сохранено с NPM-13),
`config/crazedns-failover-groups.yaml`, `config/crazedns-failover.json`.
Резерв — VPNUS Германия grp-43-3, VLESS с UDP, отдельный от OLCRTC.
Его точное имя и провайдер задаются в YAML. Если узел исчезнет из подписки,
он перестанет проходить проверку; не подменять его случайным AUTO.

Проверки каждые 30 секунд обращаются через каждый кандидат непосредственно
ко всем шести облачным серверам на TCP 8090. Ожидаемый ответ без параметров обратного
туннеля — HTTP 410, подтверждённый на этих серверах. Нужны шесть успешных
ответов из шести. Это проверка доступности облачного порта, не полного
пользовательского HTTPS-сеанса; полноценный доступ проверяется отдельно с VPS.
Для активного канала также отслеживаются ответы реального UDP/9-агента.
После смены канала есть 60 секунд на установление связи; 75 секунд без новых
UDP-ответов исключают такой канал на пять минут.

Два неуспешных цикла активного канала переключают на проверенный резерв.
Возврат на канал с более высоким приоритетом требует трёх успешных циклов
и не менее двух минут после предыдущего переключения. Если все недоступны,
сохраняется последний выбор: вращать заведомо мёртвые маршруты бесполезно.
При переходе закрываются только TCP/UDP-сеансы группы CrazyDNS к известным
облачным адресам и портам. Следующий keepalive регистрирует канал заново.
Остальные группы и пользовательские подключения не закрываются.

Установка после слияния в master и по запросу пользователя:

1. Приватная резервная копия активного Mihomo config; добавить три группы,
   заменить только 14 правил NPM-13, проверить `mihomo -t` и исходный хэш,
   атомарно заменить файл и выполнить горячую загрузку. При ошибке откатить.
2. Установить helper в `/opt/share/homenet/crazedns-failover/`, JSON в
   `/opt/etc/homenet/crazedns-failover.json`, init `S99homenet-crazedns` в
   `/opt/etc/init.d/`. JSON и резервные копии — mode 600. Если контроллер
   использует secret, добавить его только в приватный JSON на роутере,
   не в репозиторий. Нужен установленный `/opt/bin/python3` без внешних модулей.
3. Выполнить `python3 crazedns-failover.py --probe --config <private.json>`.
   Затем запустить init. Проверить `/opt/var/lib/homenet/crazedns-failover/state.json`
   и `/opt/var/log/homenet-crazedns.log`: секреты в них не записываются.
4. При первой миграции закрыть прежние известные сеансы NPM-13, которые ещё
   не имеют `CrazyDNS` в цепочке. Все новые сеансы должны содержать эту группу.
5. Проверить публичные HA/трекер/Account/каталог с VPS через DNS и каждый IP.
   Изолированный тест отказа: на время выбрать REJECT в скрытой группе
   `CrazyDNS OLCRTC`, дождаться автоматического резерва, проверить TCP и UDP,
   вернуть OLCRTC и дождаться штатного возврата. Общий OLCRTC не отключать.

Локальные проверки: `python -m unittest discover -s scripts -p test_crazedns_failover.py -v`.
Они проверяют подтверждение отказов, задержку возврата, потерю UDP при живом
HTTP и область очистки соединений. Повторный запуск helper защищён flock.

Откат: остановить только `S99homenet-crazedns`, вернуть правилам цель OLCRTC,
проверить и горячо загрузить конфиг; убрать три новые группы после удаления
ссылок. Поздние чужие изменения не заменять полной старой копией.
Пул IP — обнаруженный снимок: при изменении Netcraze обновить и правила,
и `cloud_ips`/проверочные адреса через задачу.
