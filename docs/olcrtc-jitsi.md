# OLCRTC: Jitsi и проверка площадок

NPM-104 / MIHOMO-21, проверено 31.10.2026.

## meet.egovm.ru

HTTPS-адрес площадки отличается от её XMPP-домена `meet.jitsi`.
`config.js` возвращает 403 для `Go-http-client/2.0` и полного User-Agent
Firefox из библиотеки; общий `Mozilla/5.0` получает 200. При неудаче
обнаружения библиотека молча использовала HTTPS-имя как XMPP-домен, поэтому
Prosody отвечал `This server does not serve meet.egovm.ru`.

В mihomo закреплена локальная копия `github.com/zarazaex69/j v0.0.1` с
исправлением запроса, полным ограниченным чтением ответа и диагностикой
ошибок. Серверная сборка HomeNet применяет тот же `olcrtc_jitsi.patch`.
Маркер `92b2332-jitsi-config-v1` отличает её от старого бинарника; версия
протокола olcrtc остаётся прежней.

Лёгкая утилита `mihomo/scripts/jitsi-check` проверяет гостевой вход в MUC
через сокеты с mark 255 и DNS Яндекса. С исправленной библиотекой вход
с роутера в meet.egovm.ru и meet.riddlerx.org прошёл. Это проверка
сигнализации; полноценный туннель нужно проверить после обновления обеих сторон.

## Телемост

Гостям запрещено создавать встречи, но в готовую комнату можно входить
без аккаунта. Для предоставленной комнаты API успешно выдал гостевые
данные. Роутер достигает `goloom.strm.yandex.net:443`, а VPS VDSKA
`213.155.28.79` получает таймаут TCP до `87.250.254.244:443`. В журнале
сервера — `dial ws: dial tcp ... i/o timeout`, на роутере — ожидание
ответа второй стороны и 504. Google и Cloudflare DNS возвращают тот же
IPv4; рабочего IPv6-маршрута на VPS нет. Гостевой вход комнаты здесь
не является причиной отказа.

## Ограничения диагностики роутера

`/tmp` — tmpfs. Бинарники, архивы и дампы хранить в отдельном каталоге
на диске, например `/opt/var/tmp/<ключ-задачи>`, и удалять после проверки.
Не запускать второй полный mihomo ради проверки сигнализации: при 1 ГБ
RAM это создаёт давление на память и swap. Для `jitsi-check` достаточно
`GOMEMLIMIT=24MiB GOGC=30`; перед и после проверки сверять память и
`http://192.168.1.1:63412/health/ready`.
