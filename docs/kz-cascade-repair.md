# Каскад Казахстана: NPM-123

10 ноября 2026. Каскад был указан в конфиге и API, но общий вход «Обходы» оказался закреплён на PAUK Чехия. Через него REALITY Казахстана перестал проходить аутентификацию. Сам вход отвечал из CZ95.85.238.48. TCP SYN с этого адреса подтверждён на VPS; служба Xray active, ключи клиента/сервера совпадают, разница часов менее секунды.

Изолированный Mihomo с тем же клиентом: напрямую timeout, через Чехию TLS EOF, через PAUK node-06 OpenAI401, node-02/03 TLS EOF. Проверка не меняла рабочие маршруты. `python -X utf8 scripts/probe-kz-cascade.py` повторяет сравнение во временных приватных конфигурациях и завершает тестовые процессы.

Исправление: служебная ручная группа «Каскад Казахстана», только проверенный node-06 из существующего провайдера PAUK; dialer-proxy Казахстана указывает на неё. Провайдерские узлы нельзя указать непосредственно как dialer-proxy: Mihomo ищет имя среди статических прокси/групп. Остаётся одна пользовательская группа ИИ и один конечный KZ-узел. Текущий ручной выбор ИИ и закрепление общей группы «Обходы» сохраняются.

Из merged master скопировать `scripts/repair-kz-cascade.py` в приватный `/opt/etc/mihomo/recovery-NPM-123/repair.py`, запустить `apply`. Скрипт проверяет config/check и CAS, сохраняет приватную копию, меняет только proxies/proxy-groups, проверяет выход KZ и сохранение выбора. При ошибке возвращает прежние секции, если SHA исключает параллельное редактирование.
