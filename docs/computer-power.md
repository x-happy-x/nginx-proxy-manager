# Питание компьютеров — NPM-105

Связано: INFRA-87 (HA, Matter, имена и телевизор), INFRA-86 (свет у порога).

В карточке физического компьютера доступны «Включить» и «Выключить».
Включение отправляет WoL к заданному MAC через IPv4 broadcast, UDP девять.
Выключение вызывает ограниченный агент: Windows `shutdown.exe /s /t 0`
без принудительного закрытия приложений, Linux `systemctl poweroff` с уже
имеющимися правами пользователя. Розетки питания не переключаются.

В настройках компьютера включается управление питанием и задаются `mac`
и `broadcast`. Поле `power_enabled` по умолчанию выключено, поэтому добавление
функции не даёт права выключать существующие серверы и VM.
Для агента версии 1.3.0 требуется отдельное разрешение
`--allow-power-actions` (`-AllowPowerActions` в Windows-установщике).
Права Docker и WSL остаются независимыми.

Состояние берётся из свежего снимка агента. При его отказе отдельно
проверяется доступность SSH-порта: доступный порт означает включённый
компьютер, недоступный — выключенный или потерявший сеть. Старое наблюдение
показывается как неизвестное. Выключение разрешается только при свежем
снимке агента с явным разрешением, включение — и при отсутствии связи.
Сведения о состоянии не подтверждают аппаратную поддержку пробуждения.

Для HA Core предоставляет ровно один отдельный endpoint:
`GET/POST /api/pc/power/integration`. Серверный токен 0600 хранится в
`/opt/etc/homenet/core/credentials/pc-power.token`; он разрешает только список
компьютеров с включённым управлением и команды `{"host":"pc-a","on":true}`.
Он не подходит для других API и не выдаётся браузеру. Core переводит запрос
на приватный PC worker с его собственным credential. Worker повторно проверяет
цель, разрешения, свежесть состояния и конфликтующие операции.
Для legacy manager оставлен отдельный scoped endpoint
`/api/integrations/pc-power` с токеном из `PC_DIR/power-token`.

Адресная подготовка двух пользовательских компьютеров:

- PC-X, кабинет: `192.168.1.10`, Ethernet `b0:82:e2:30:92:8d`;
- PC-A, зал: `192.168.1.20`, Wi-Fi `ac:82:47:4b:eb:d7`.

`scripts/configure-pc-power.py` проверяет hostname PC-A по существующему
SSH-ключу HomeCloud. Для текущего PC-X агент устанавливается локально с
правами администратора через `scripts/install-local-pc-power.ps1 -PublicKey ...`:
файл ключей OpenSSH защищён от обычного пользователя. Затем configure
проверяет статус и SHA256 установленного бинарника. SSH host key PC-X берётся
из локального публичного ключа или от того же локального sshd через loopback;
устаревший known_hosts пользователя не меняется.
Установщик сохраняет старый агент и authorized_keys, оставляет прежние
разрешения Docker/WSL, добавляет только разрешение питания. На роутере
сохраняются hosts/known_hosts, добавляются PC-A и WoL, остальные машины
остаются без управления питанием. Config API обновляет только PC worker.

Из master после слияния:

```powershell
$env:GOFLAGS='-buildvcs=false'
node scripts/build-modules.mjs amd64 1.0.105 --only=pve,pc
node scripts/build-modules.mjs arm64 1.0.105 --only=pve,pc --reuse-ui
./pc-agent/build.ps1
# На самом PC-X один раз запустить scripts/install-local-pc-power.ps1
# в PowerShell администратора с публичным ключом интеграции HomeNet.
python scripts/deploy-pc-power.py --apply
python scripts/configure-pc-power.py --apply
```

Поставки Core/PC/PVE 1.0.105 неизменяемые. Обновление проверяет SHA256
перед переключением, останавливает Core штатно и использует `platformctl apply`
с журналом операций. При отказе readiness возвращаются прежние версии
модулей через lifecycle rollback и прежний Core current. Роутерный nginx,
Mihomo, Account и DMS не перезапускаются. Резервные данные находятся в
`/opt/etc/homenet/core/backup/NPM-105-*` и `/opt/etc/homenet/pc/backups/NPM-105-*`.
Legacy deploy-router.py на модульной установке не применяется.

Физическое выключение PC-X во время работы агента не тестируется.
Для PC-A на Wi-Fi возможность WoL из полного выключения зависит от
адаптера/прошивки; наличие включённого WakeOnMagicPacket не доказывает её.
