# LMS egress

NPM-126 adds a narrow server integration. `GET /api/lms/egress?node=<approved node UUID>&host=<optional exact hostname>` uses its own Core `credentials/lms-egress.token` (32+ random characters). Browser Origin/cross-site and all writes are refused. It cannot authorize other HomeNet APIs. Worker credentials remain private to Core.

The VPN worker reads `MIHOMO_STATE_DIR/lms-egress.json` (root0600). It contains `nodes` (approved node UUID to private source IP) and private `routes` (`id`, `label`, `proxy`, `listen`, `port`, `username`, `password`). The public contract exposes only IDs/labels/engine support and observations of the approved source IP. An optional exact host filter prevents mistaking another CDN path for the requested URL. No matching connection means no observation.

An Account administrator can explicitly provision dedicated routes using `POST /api/integrations/vpn/api/core/lms-egress` with `{listen: "<private LAN IP>", nodes: {"<node UUID>": "<private IP>"}, routes: [{id, label, proxy}]}`. Existing outbound names must be present in Mihomo; rejecting outbounds are refused. This operation generates authenticated HTTP listeners on34000–34999, with `proxy` bound to each chosen outbound and a separate strong password. It preserves shared groups and all unowned listeners; name/port collisions are rejected. Credential registry commits atomically after ordinary Mihomo validation/reload, with rollback on error. Repeating an unchanged configuration skips reload. Provisioning is a deployment operation, not part of a read-only UI check. Removing routes may affect running users of those listeners, so deployment must verify there are no active routed jobs.

The listener format follows the official [Mihomo HTTP listener](https://wiki.metacubex.one/en/config/inbound/listeners/http/) and [common listener fields](https://wiki.metacubex.one/en/config/inbound/listeners/). A bound group can choose a different final outbound over time; configured route and observed chains must be displayed separately.

Deploy Core/VPN1.6.126 from merged master using `scripts/build-modules.mjs arm64 1.6.126 --only=vpn --reuse-ui` and `scripts/deploy-lms-egress.py --apply`; the existing UI artifacts are reused because no HomeNet UI changes. Root token and listener credentials must travel through SSH captured pipes, never command output or browser settings. Bind only LAN, restrict the new dedicated ports to configured source IPs in the managed firewall, and keep the registry outside LMS storage roots. Node/Router integration is tracked by LMS-18/LMSC-17; private config mount by INFRA-133.
