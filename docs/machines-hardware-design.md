# NPM-96 — аппаратная схема «Машин»

Запрос: «Добавь поддержку неизвестных железок и схему улучши (сначала дизайн)».

Интерактивный макет: [machines-hardware-design.html](machines-hardware-design.html).
По умолчанию макет использует реальные снимки трёх Proxmox-хостов и локального
PC-X. Демосценарии выбираются отдельно. Это локальный просмотр кандидатов агентов;
установленные агенты, службы и SSH-права не меняются.

Запуск из корня репозитория (Windows):

```powershell
New-Item -ItemType Directory -Force .local/qa/NPM-96 | Out-Null
Push-Location backend
go build -buildvcs=false -o ../.local/qa/NPM-96/pc-agent.exe ./pcagent
Pop-Location
node scripts/collect-hardware-design.mjs
node scripts/hardware-design-preview.mjs 48690
```

Открыть `http://127.0.0.1:48690/docs/machines-hardware-design.html`.
Снимки хранятся в игнорируемой `.local/qa/NPM-96/hardware.json`, не в Git.
«Собрать заново» запускает чтение, сохраняет новый снимок и обновляет макет.
Сборщик использует существующие SSH-подключения к `192.168.99.10/20/30`, исполняет
кандидат Python-коллектора через stdin и не устанавливает его на серверах.
На PC-X выполняется отдельный read-only запрос `hardware`, без Docker/WSL.
Сервер слушает только loopback; список файлов и команды фиксированы. Повторный
сбор требует same-origin POST с отдельным заголовком, произвольные адреса и
команды из браузера не принимаются.

## Композиция

Четыре компактных переключателя машин, одна крупная плата выбранной машины,
панель выбранного компонента справа. На средней ширине панель переходит под
плату. На телефоне доступны увеличение с внутренней прокруткой и текстовый
список выбора компонентов. Общие поверхности и темы используют токены портала.

На плате сохраняются зоны CPU, RAM, графики, системной логики, сети и
накопителей. Ethernet и Wi-Fi имеют разные силуэты. При определённых CPU,
памяти и накопителях дополнительные PCI/USB скрыты с основной схемы. Они
сохраняются в полном инвентаре, с поиском и фильтром «Не распознаны».
Расположение логическое: не обещаем соответствие реальной материнской плате.
Расширенная реализация должна группировать произвольное число компонентов,
показывать счётчик и раскрытие группы, не обрезать инвентарь до 2 NIC/3 дисков/4 DIMM.

## Состояния сведений

| Состояние | Отображение | Значение |
| --- | --- | --- |
| Определён | Модель и доступные показатели | Сведения переданы агентом |
| Частично | Известные поля + конкретные пропуски | Например, объём ОС известен, DIMM нет |
| Не определён | Штриховка, общий символ, исходный ID | Устройство обнаружено, назначение или модель не распознаны |
| Нет данных | Нейтральный пунктир, причина | Не собирается, не передано или недоступно |
| Пустой слот | Контур слота | Только если источник явно сообщил пустой слот |

Статус определения отделён от здоровья и доступности. Неизвестное устройство
не получает статус неисправности. Отсутствие температуры не превращается в 0 °C.
Отсутствие GPU в ответе не доказывает её физическое отсутствие. Название платы
не является подтверждением модели её чипсета. Скорость Ethernet сама по себе
не даёт основания предупреждать о деградации.

Выбор компонента раскрывает известные поля, источник, шину, идентификатор,
драйвер и исходные сведения при наличии. Пользовательское название и вид
меняют только оформление: исходное определение и идентификаторы сохраняются.
В макете такие изменения живут только до перезагрузки страницы.

## Сценарии макета

- s1: обычный мини-ПК с одним NVMe.
- s2: две GPU, два накопителя, Ethernet + Wi-Fi, неизвестный PCI-компонент,
  аудио и USB. Дополнительные компоненты — явно обозначенный демосценарий;
  PCI ID `ffff:0001` синтетический и не относится к реальному устройству.
- s3: GPU не передана, серия B850 получена из имени платы.
- PC-X: неполный Windows-инвентарь. Объём памяти ОС не выдаётся за сумму DIMM;
  восемь томов не выдаются за восемь физических накопителей.

## Уже добавленный сбор

- pc-agent 1.2.0: опциональный `hardware` в v1 snapshot и отдельный запрос
  `hardware`; независимые провайдеры Windows CIM, полный PCI/USB PnP-инвентарь,
  плата/BIOS, CPU, DIMM и сырые SMBIOS type 17 для пустых слотов, GPU/драйвер,
  физические/виртуальные диски, привязка томов, NIC. Датчики существующего
  LHM/OHM-провайдера, NVIDIA через установленный nvidia-smi, Storage reliability
  при доступности. Лимит 12 секунд, неудача одного источника не удаляет другие.
- Linux pc-agent: sysfs, lscpu, DMI, PCI/USB, lsblk, доступные hwmon и SMART.
  SMART читает доступные данные с запретом пробуждения standby-дисков.
- pve-agent 1.5.0: полный PCI/USB-инвентарь, объём установленных DIMM отдельно
  от памяти ОС, явные состояния и подписи слотов, тип сетевого адаптера.
- Manager сохраняет опциональный hardware-документ без потери неизвестных полей.

Слоты в макете следуют записям DMI/SMBIOS. Пустые, занятые и неизвестные
состояния различаются. Все реальные подписи доступны по нажатию; `Bank Locator`
различает одинаковые `Device Locator` в разных каналах. Если известно только
число свободных слотов, точные подписи не придумываются. На PC-X прошивка
передаёт `P0 CHANNEL A/B · DIMM 0/1`, а не обозначения A1/A2/B1/B2 на текстолите.

На PC-X чтение CPU-температур недоступно без отдельного провайдера, а Storage
reliability возвращает отказ текущему пользователю. Эти пробелы объясняются в
интерфейсе; агент не устанавливает драйверы и не запрашивает повышение прав.
Строка `HealthStatus` ОС не выдаётся за SMART self-test.

## Реализация в React

Согласованный экран перенесён в «Машины → Железо» и в аппаратную вкладку
отдельной машины. Общий адаптер находится в
`frontend/src/features/machines/hardware-model.js`: его используют React,
HTML-макет и тесты. TypeScript получает типизированную модель через соседний
`hardware-model.d.ts`; исходные расширяемые аппаратные записи не отбрасываются.

Сохранены схема 700×430, ортогональные линии, точные пустые/занятые слоты,
выбор компонента мышью и клавиатурой, увеличение на телефоне, датчики, панель
компонента и полный инвентарь с поиском/фильтрами. Устройства PCI/USB скрыты
с основной платы, когда CPU, DIMM и накопители определены. В инвентаре можно
задать локальную подпись неизвестному устройству, не изменяя исходные сведения.

Идентичность компонентов зависит от адреса/ID устройства и подписи слота,
а не от позиции в массиве. Изменение порядка ответа агента не переключает
выбранный диск на другой. Старые PC-агенты показывают логические тома и
память ОС без вымышленных физических дисков или DIMM; физические ядра не
подменяются количеством логических потоков. Недоступная машина сохраняет
последний инвентарь с датой. Совместимость работает и при отключённом PVE/PC.

Для изолированного просмотра основного интерфейса используйте
`PREVIEW_HARDWARE_FILE=.local/qa/NPM-96/hardware.json` вместе с
`PREVIEW_PVE=fake PREVIEW_PC=fake node scripts/modular-preview.mjs pve,pc 48674`
после `node scripts/build-modules.mjs amd64 1.0.0 --only=pve,pc`.
Аппаратный инвентарь в таком просмотре взят из сохранённых реальных снимков;
остальные экраны и метрики используют тестовые данные. Никакие команды
управления на реальные машины не отправляются.

Код основного интерфейса готов. Кандидаты агентов не установлены на устройства,
push/выкладка не выполнялись.
