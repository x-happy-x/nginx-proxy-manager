# Хостинги

Интеграция HomeNet `hostings`, задача NPM-120. Первый провайдер — is*hosting.

## Возможности

В каталоге HomeNet откройте «Хостинги». На странице «Подключения» укажите название и API-ключ is*hosting. Страница «Серверы» показывает VPS, публичный IP, страну, CPU, память, диск, ОС по панели и состояние. Есть поиск, выбор подключения и ручное обновление. Опрос выполняется раз в пять минут; при ошибке остаётся последний успешный снимок с предупреждением. Несколько аккаунтов одного провайдера поддерживаются (до восьми).

Редактирование с пустым ключом сохраняет действующий ключ. «Отключить» удаляет только локальное подключение HomeNet. Изменение, удаление VPS и управление SSH не реализованы: запросы к провайдеру только GET.

## Хранение и API

Worker слушает loopback `127.0.0.1:63507`; доступ через штатный авторизованный Core. Данные находятся в `HOSTINGS_DIR` (по умолчанию `/opt/etc/homenet/hostings`). `accounts.json` содержит ключи, права 0600, каталог 0700. Ключи принимаются только на запись и не возвращаются браузеру. `inventory.json` содержит только разрешённые поля серверов; SSH-пароли и прочие поля `access` ответа провайдера не декодируются и не кэшируются. Редиректы API запрещены, адрес API фиксирован.

- `GET /api/hostings/overview`: безопасный снимок.
- `POST /api/hostings/refresh` с `{}`: обновление снимка.
- `POST /api/hostings/accounts`: `{id?,name,provider:"ishosting",token}`.
- `POST /api/hostings/accounts/remove`: `{id}`.

Официальный API: https://api.ishosting.com. Нужен заголовок `X-Api-Token`, User-Agent приложения, пагинация `/vps/list?limit=50&offset=0`, затем `/vps/{id}`. Ошибки провайдера преобразуются в сообщения без его тела ответа. Интеграция не предоставляет SSH-реквизиты интерфейсу.

## Сборка и установка

`node scripts/build-modules.mjs arm64 1.6.120 --only=hostings` собирает модуль и Core с обновлённым каталогом. После проверки и слияния в master выполните `python scripts/deploy-hostings.py --apply`. Скрипт сверяет хэши staged-релизов, делает резервную копию Core, проверяет план lifecycle, устанавливает интеграцию и проверяет готовность. При сбое восстанавливает прежний Core и удаляет только новую регистрацию модуля, сохраняя данные. Повторная установка поверх уже установленного модуля запрещена: дальнейшие версии обновляются через lifecycle update.

Проверка: `go test ./manager -run TestHostings`, тесты с `-tags=integration_worker`, тесты `./internal/integration`, TypeScript и обе сборки. Тесты проверяют отсутствие секретов в ответах/кэше, сохранение ключа при пустом редактировании, очистку снимка при замене ключа, блокирование редиректа и некорректного ID, сохранение последнего снимка при 403 и защиту повреждённого файла ключей. Изолированный UI: `PREVIEW_MODULE_VERSION=1.6.120 node scripts/modular-preview.mjs hostings 48680`.
