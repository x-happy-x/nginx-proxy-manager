# CrazyDNS: стабильный маршрут облачных соединений

После NPM-106 правила используют группу `CrazyDNS` с автоматическим выбором
DIRECT/OLCRTC/резерва. Актуальная установка и проверки описаны в
[crazedns-failover.md](crazedns-failover.md); ниже сохранена диагностика NPM-13.

NPM-13. Фрагмент `config/crazedns-olcrtc.yaml` закрепляет облачные обратные
соединения CrazyDNS за существующей группой `OLCRTC`. Это дополнение к текущим
`rules`, а не самостоятельный конфиг Mihomo.

На роутере CrazyDNS работает в режиме `cloud`: WAN имеет частный адрес,
а входящие HTTPS-запросы доставляются через обратные TCP-соединения к серверам
`ndns*.omni.ru:8090`. У перехваченных соединений поле `host` часто пустое.
Правило только для `crazedns.ru` их не охватывает.

При диагностике обычное `GEOIP,RU,РФ` отправляло эти соединения то через OLCRTC,
то через другую цепочку fallback. С VPS воспроизводились таймауты TLS ещё до
ответа приложения. Закрепляем TCP 8090 и UDP 9/4044 шести обнаруженных облачных IP;
для соединений с известным именем добавлено правило `ndns*.omni.ru`.
Локальный split DNS и остальные маршруты сохраняются.

Обнаруженные при проверке с VPS узлы: `ndns111.omni.ru` — 31.135.14.238,
`ndns112.omni.ru` — 178.250.154.58,
`ndns113.omni.ru` — 95.213.212.50, `ndns114.omni.ru` — 185.162.93.96,
`ndns115.omni.ru` — 87.228.71.67, `ndns116.omni.ru` — 5.35.2.42. Публичный DNS
домашних доменов при проверках выдавал разные пары из пяти адресов ndns112–116.
Адрес ndns111 включён для покрытия отдельной записи соседнего облачного узла.
Одинаковые ответы для ndns110 и ndns117–120 соответствуют общему DNS wildcard;
эти адреса не приняты за подтверждённые обратные соединения и не добавлены.

Агент также использует UDP keepalive на порту 9 (наблюдался к 185.162.93.96)
и UDP 4044 при первоначальной проверке серверов. Эти каналы нужно закрепить
вместе с TCP: до изменения keepalive продолжал идти через «РФ»/«Обходы».
Текущий узел OLCRTC объявляет поддержку UDP. Назначение портов описано в
[документации Keenetic, пункт 4](https://support.keenetic.com/buddy-6-se/kn-4410/en/21741-internal-service-traffic.html).
Перевод keepalive не требует перезапуска облачного агента: закрыть только
старую UDP-сессию этого адреса/порта в контроллере и дождаться следующего пакета.

Применять после слияния в master, в рамках задачи и по запросу пользователя:

1. Прочитать действующий `/opt/etc/mihomo/config.yaml` через SSH, сохранить
   приватную резервную копию на роутере, проверить наличие группы `OLCRTC`.
   Секреты и конфигурацию прокси не выводить в терминал или git.
2. Добавить отсутствующие правила из фрагмента перед существующими `rules`.
   Сохранить порядок остальных правил. Проверить, что другие секции побайтно
   или семантически не изменились. Повторное применение не создаёт дубликатов.
3. Записать кандидат в приватный файл рядом с конфигом и проверить:
   `/opt/sbin/mihomo -t -d /opt/etc/mihomo -f <candidate>`.
   Вывод валидатора может содержать секреты: сохранять приватно, не публиковать.
4. Перед атомарной заменой повторно сравнить хэш действующего файла с исходным.
   При несовпадении отменить применение и подготовить кандидат заново.
5. Выполнить горячую загрузку через `PUT /configs?force=false` контроллера
   Mihomo с JSON `{"path":"/opt/etc/mihomo/config.yaml"}`. При ошибке вернуть
   резервную копию и повторно загрузить её. Не перезапускать роутер/XKeen.
6. Снять фактические цепочки `/connections`: новые соединения к облаку на TCP 8090
   и UDP 9/4044 должны совпадать с правилом `AND` и проходить через `OLCRTC`. Старые
   соединения при необходимости закрывать только по их ID, адресу и порту.
7. С внешнего `olcrtc-vps` выполнить несколько раундов HTTPS GET для HA,
   трекера, Account и каталога: обычный DNS и `curl --resolve` для каждого
   облачного IPv4. Использовать проверку сертификата и ограничение времени.

Список IP — снимок обнаруженного пула, а не гарантия его неизменности.
Если Netcraze сменит серверы и `host` останется пустым, сверить `show ndns`,
публичный DNS и реальные `/connections`, затем обновить фрагмент через задачу.
IPv6 на текущем Mihomo отключён. Доступность OLCRTC остаётся необходимой:
автоматического возврата этих соединений в группу «РФ» намеренно нет.

Откат: удалить только точные строки из этого фрагмента, проверить конфиг и
горячо загрузить. Полную копию возвращать лишь если после применения никто
не менял конфигурацию; иначе сохранить более поздние изменения.
