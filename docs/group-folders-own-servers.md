# Папки групп и свои серверы

NPM-124 исправляет трактовку запроса: пользовательские папки содержат группы маршрутизации, а не серверы. На вкладке «Группы» есть сворачиваемые папки, карандаш редактирования, создание/переименование/удаление. Одна группа находится в одной папке; при переносе она удаляется из прежней. Не назначенные группы показываются в «Без папки». Папки сохраняются на роутере в group-folders.json через revision/CAS, доступны с других устройств и не меняют Mihomo-правила. Старое хранилище ошибочно добавленных папок узлов сохраняется, но UI его больше не использует. Узлы по-прежнему можно сортировать по пингу и группировать по источнику/стране.

Начальные папки: «ИИ» (ИИ и Каскад Казахстана), «Остальные» (прочие пользовательские группы). Пользователь может изменить состав и имена. Данные отсутствующей временно группы сохраняются.

`/opt/etc/mihomo/own-servers.yaml`0600 содержит список proxies (Казахстан · VLESS) и olcrtc-servers (все3 сохранённых серверных профиля OLC с приватными параметрами). Главный config.yaml подключает `proxy-files: [./own-servers.yaml]`; имени KZ в корневом proxies больше нет. MIHOMO-28 сохраняет статическое имя импортированного узла, поэтому ИИ и health-check-via продолжают ссылаться на него. Основная ИИ явно выбирается на KZ; автогруппа входов сохраняется без фиксации ноды.

OLC-мастер читает и обновляет профили в общем файле, сохраняя прокси без изменения. В старом olcrtc.json остаются runtime-флаги, события/проверки и состояние процесса; серверные профили не дублируются. Если сохранение инвентаря не удалось, в runtime JSON остаётся резервный список с own_servers_fallback=true. При повреждённом файле автонастройка останавливается, файл не затирается. Рабочие OLC-варианты по-прежнему обслуживаются стандартным файловым провайдером olcrtc.yaml; сейчас вариантов нет, серверных профилей3. Миграция не создаёт неработающие узлы.

Из merged master: `python scripts/deploy-group-folders.py --apply` устанавливает Core/VPN1.6.125 с lifecycle/rollback, затем перенести `scripts/migrate-own-servers.py` в recovery-NPM-124/migrate.py и запустить apply на роутере. До миграции устанавливается Mihomo MIHOMO-28. Миграция сохраняет приватные копии, проверяет config/check и CAS, сохраняет криптографические поля, обновляет инвентарь, выбирает KZ, проверяет выход и регенерацию маршрутов. При ошибке возвращает свои секции и актуальные OLC-профили. Старые ИИ-соединения к другим выходам закрываются адресно после успешной проверки KZ.
