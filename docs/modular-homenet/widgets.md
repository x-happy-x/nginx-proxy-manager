# Главная из виджетов интеграций (ui_api 2)

Задача проектирования: NPM-new (номер — после заведения в трекере). Дата: 14 октября 2026.
Исходная точка: master 25b688d. Макеты — холст «HomeNet — редизайн», страница
«Переработка», ряд «Обзор Core из виджетов интеграций»: обычный вид, режим
«Изменить», модуль недоступен.

## Зачем

Сейчас «Обзор» Core показывает заголовок и список установленных интеграций.
Модуль умеет одно — встроить свой интерфейс целиком (`IntegrationModule.mount`
в `frontend/src/platform/sdk.ts`). Чтобы главная отвечала на вопрос «всё ли
работает», Core должен получать от модулей короткие сводки и собирать из них
страницу. Пользователь выбирает, какие сводки видеть и где.

## Что даёт модуль

Модуль с `ui_api: 2` может отдать Core три вещи:

1. **Виджеты** — карточки для главной, объявляются в манифесте.
2. **Внимание** — список проблем (`attention`).
3. **Задачи** — что сейчас выполняется и насколько (`tasks`).

Внимание и задачи — не виджеты: Core показывает их всегда, сводя все модули в
один список. Пользователь не может их убрать, чтобы проблема не потерялась.

Модуль с `ui_api: 1` работает как раньше; на главной у него плитка «Открыть».

## Манифест

`backend/internal/integration/manifest.go`, структура `UI` получает поле `Widgets`:

```json
"ui": {
  "entry": "entry.js",
  "pages": [{"id": "vpn", "title": "VPN"}],
  "widgets": [
    {
      "id": "channel",
      "title": "Канал провайдера",
      "kind": "status",
      "sizes": ["s", "m"],
      "data": "/api/vpn/widgets/channel",
      "refresh": 30,
      "modes": ["simple", "pro"],
      "default": {"simple": 10, "pro": 10},
      "page": "vpn"
    }
  ],
  "summary": {"attention": "/api/vpn/summary/attention", "tasks": "/api/vpn/summary/tasks"}
}
```

| Поле | Смысл |
| --- | --- |
| `id` | уникален внутри модуля; полный ключ — `<модуль>/<id>` |
| `kind` | `stat`, `status`, `list`, `progress`, `series`, `bars` или `custom` |
| `sizes` | из `s` (3 колонки из 12), `m` (6), `l` (12); на узком экране все — во всю ширину |
| `data` | путь данных; **обязан** лежать внутри `backend.paths` модуля, иначе манифест отклоняется |
| `refresh` | как часто данные устаревают, секунды, 10…3600 |
| `modes` | в каких режимах виджет доступен в каталоге |
| `default` | порядок в стандартной раскладке режима; нет ключа — не входит в стандартную |
| `page` | куда ведёт клик по виджету |

Проверка манифеста: не больше 16 виджетов на модуль, `id` — `[a-z0-9-]{1,32}`,
заголовок до 48 символов, `data` и `summary` — внутри `backend.paths`.

## Данные стандартных виджетов

Общая оболочка ответа `GET <data>`:

```json
{"state": "ok|warn|bad|unknown", "updated_at": "2026-10-14T00:24:00Z", "note": "с 15:14 · Яндекс ✓ Google ✗", "body": { ... }}
```

`state` красит рамку и точку виджета. `updated_at` — когда модуль получил эти
данные сам, а не время ответа. `note` — одна строка под значением. Только
текст: Core не вставляет HTML из данных.

| `kind` | `body` |
| --- | --- |
| `stat` | `{"value": "255,8", "unit": "ГБ", "delta": "-12% к прошлому месяцу"}` |
| `status` | `{"label": "Белые списки", "items": [{"text": "Яндекс", "ok": true}, {"text": "Google", "ok": false}]}` |
| `list` | `{"items": [{"text": "…", "state": "ok", "value": "205 мс", "page": "vpn/servers"}], "more": 12}` — до 8 строк |
| `progress` | `{"value": 318, "total": 690, "label": "Проверка серверов", "eta_s": 180}` |
| `series` | `{"unit": "мс", "points": [["2026-10-14T00:00:00Z", 412], ...], "bands": [{"from": "...", "to": "...", "label": "белые списки"}]}` — до 288 точек |
| `bars` | `{"unit": "серверов", "bars": [{"label": "0–10%", "value": 588}, ...], "scale": "linear|sqrt"}` — до 24 столбцов |

Размер ответа — до 16 КБ на виджет; больше — Core показывает ошибку виджета.

## Свои виджеты (`kind: "custom"`)

Для того, что не ложится в стандартные типы. Модуль экспортирует из `entry.js`:

```ts
export const widgets = {
  "requests-by-hour": { mount(el: HTMLElement, host: Host, ctx: {size: "s"|"m"|"l", mode: "simple"|"pro"}) { /* … */ return () => {}; } }
};
```

Core монтирует каждый свой виджет в отдельный shadow root с собственной
границей ошибок (как страницы модулей сейчас). Исключение или зависание
дольше 3 секунд — виджет показывает «не отрисовался» с кнопками
«Перезагрузить виджет» и «Подробности ошибки»; остальная главная работает.
Данные свой виджет берёт сам через `host.api`, тем же путём `data`.

Стандартные виджеты предпочтительнее: единый вид, работают при сломанном UI
модуля, на главной нет чужого кода.

## Внимание и задачи

```json
GET <summary.attention>
{"items": [{"id": "headscale-health", "severity": "critical|warning|info", "text": "Headscale: ни один сервер не проходит /health", "since": "…", "action": {"label": "Разобрать", "page": "vpn/groups/headscale"}}]}

GET <summary.tasks>
{"items": [{"id": "scan-router", "label": "Проверка серверов", "value": 318, "total": 690, "step": "2 из 6", "eta_s": 180, "cancel": "/api/vpn/tasks/scan-router/cancel"}]}
```

Core сортирует внимание по `severity`, затем по `since`, и подписывает
источник. Задачи Core добавляет и свои: обновление модулей, восстановление.

## Как Core собирает главную

`GET /api/core/home?mode=pro` — один запрос браузера на всю страницу.

1. Core берёт раскладку пользователя для режима (или стандартную).
2. Параллельно запрашивает данные видимых виджетов, внимание и задачи у
   включённых модулей; таймаут на модуль — 2 секунды.
3. Ответ модуля кэшируется на `refresh` секунд; при таймауте или ошибке Core
   отдаёт последний удачный ответ с `stale: true` и временем.
4. Модуль выключен, обновляется или остановлен — его виджеты `unavailable`
   с причиной («обновляется», «выключен»), последние данные серым.

Модуль отвечает из того, что уже собрал фоновыми проверками. Эндпоинт
виджета не запускает проверок и не ходит в сеть: на роутере около 150 МБ
свободной памяти, главную открывают часто.

Браузер обновляет главную раз в 30 секунд, пока вкладка видима.

## Раскладка

- Хранится в Core: `STATE/layouts/<login>.json`, отдельно для `simple` и `pro`.
- Формат: `{"v": 1, "pro": [{"w": "vpn/channel", "size": "s"}, ...], "simple": [...]}` —
  порядок в списке и есть порядок на сетке.
- `PUT /api/core/home/layout` — сохранить; `DELETE` — сбросить к стандартной.
- Стандартная раскладка — из `default` всех установленных модулей.
- Модуль удалили — его виджеты пропадают из раскладки молча; поставили новый —
  его стандартные виджеты добавляются в конец, если пользователь раскладку не
  менял, иначе только появляются в каталоге.
- Режим «Просто»: в каталоге только виджеты с `simple`; по умолчанию набор не
  больше 6, менять можно, но кнопка «Изменить» спрятана в меню «…».

## Режим «Изменить»

Каталог справа: поиск, фильтр по модулю, у каждого виджета размеры, режимы и
«на главной» / «Добавить». На сетке: перетаскивание за ручку, переключатель
размера из доступных, «×». Внизу: «Сохранить», «Отмена», «Сбросить к стандартной».
Клавиатура: виджет в фокусе двигается стрелками с Alt, размер — Alt+S/M/L.

## Безопасность

- Путь данных проверяется по `backend.paths` при установке модуля и при каждом
  запросе: Core не проксирует в чужие пути.
- Данные стандартных виджетов — только текст и числа, Core их экранирует.
- Свой виджет исполняется с тем же доверием, что и страницы модуля сейчас:
  ставить только модули из доверенного источника (как в runbook).
- Раскладка привязана к входу Account; чужую раскладку прочитать нельзя.

## Этапы

1. **Core:** поле `widgets`/`summary` в манифесте и его проверка, `ui_api: 2` в
   реестре и SDK; `/api/core/home` с параллельным сбором, кэшем и `stale`;
   раскладки; рендер шести стандартных типов; монтирование своих; сводные
   «Требует внимания» и «Идёт сейчас»; режим «Изменить».
2. **VPN:** виджеты `channel`, `services`, `servers-reliability`, `traffic-month`,
   `olcrtc`; внимание (проблемы групп, пропущенные строки подписок, OLCRTC);
   задачи (цикл проверки серверов с прогрессом — нужен счётчик в ядре).
3. **Proxy:** `domains`, `certificates`, `requests-by-hour`; внимание по
   сертификатам и недоступным доменам.
4. **Network:** `internet-lte`, `speed-by-day`; внимание при потере связи.

Для прогресса проверки серверов ядру mihomo нужен счётчик текущего обхода
(сколько проверено из скольких, когда начат) в `GET /providers/proxies/<name>`;
сейчас есть только итог (`results`, `checkedAt`). Это отдельная задача MIHOMO.

## Проверка

- Модуль с `ui_api: 1` — на главной плитка «Открыть», ошибок нет.
- Манифест с `data` вне `backend.paths` — отклонён при установке.
- Модуль не отвечает 2 с — виджет «stale» с временем, главная грузится.
- Свой виджет бросает исключение — показан «не отрисовался», остальные работают.
- Обновление модуля — его виджеты серые с причиной, после — снова живые.
- Раскладка двух пользователей не пересекается; сброс возвращает стандартную.
