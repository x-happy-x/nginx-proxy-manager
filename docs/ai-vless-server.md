# ИИ через VLESS на VPS Казахстан

NPM-119, итог 9 ноября 2026. Пользователь выбрал VLESS после проверки ограничений OLCRTC и разрешил настроить и подключить его. OLC установлен ранее, но действующим транспортом ИИ теперь является VLESS.

## Действующая схема

Роутер Mihomo → группа «Обходы» → VLESS + REALITY + Vision TCP/443 → 38.180.37.198 (Казахстан, Алматы) → сервис ИИ.

- **ИИ · сервер** — ручной выбор. Сейчас «ИИ · KZ 38.180.37.198». Можно выбрать другой узел подписки или прежнюю группу «ИИ».
- **ИИ · KZ 38.180.37.198** — fallback только двух путей к одному VPS: «VLESS KZ · каскад» и «VLESS KZ · напрямую». Другие VPS автоматически сюда не подставляются.
- **ИИ · вход каскада** — выбор первого участка; сейчас «Обходы». Доступны группы и отдельные узлы подписок для ручного выбора.

Прямой TCP с SO_MARK255 к VPS22/443/8443 сейчас даёт timeout. Поэтому рабочий путь — каскад. Вариант входа через RU не прошёл REALITY-проверку в текущей сети; доступность первого узла по обычной HTTP-пробе сама по себе не доказывает совместимость каскада. Основной вариант через «Обходы» проверен. Протокол на первом участке определяется существующей подпиской, конечный VLESS остаётся нашим сервером.

Установлен Chrome fingerprint, на клиенте включён support-x25519mlkem768, на сервере явно minClientVer1.8.2, соответствующий REALITY-версии нашего Mihomo. Последнее устраняет [известную несовместимость новых Xray и Mihomo](https://github.com/MetaCubeX/mihomo/issues/3132); включение ML-KEM соответствует требованиям новых серверов. UUID/ключи при настройке совместимости не менялись.

Секреты вне git: `/etc/homenet-xray/config.json` 0640 root:homenet-xray, `/etc/homenet-xray/client.json`0600root, на роутере `/opt/etc/homenet/mihomo/ai-vless.json`0600 и config.yaml0600. ## Применение и восстановление

`python scripts/deploy-ai-vless.py` — локальный dry-run, `--apply` — установка только из merged master. Установщик использует уже сохранённое подключение is*hosting, не содержит ключей или паролей в исходном тексте.

`ai-vless-route.py` исполняется на роутере из приватного каталога `/opt/etc/mihomo/recovery-NPM-119-vless-20261109/route.py`. prepare добавляет узлы/группы без изменения маршрута ИИ; activate переводит два существующих правила ИИ, включает watchdog420s; confirm фиксирует результат после проверки. HomeNet config/check и config/apply проверяют mihomo -t, создают резервную копию и атомарно применяют конфиг. CAS по SHA защищает от параллельного изменения.

Исходный конфиг сохранён как `original.yaml` в том же каталоге, SHA256277887637a29243a488b6f73675a0483815773575a810006bf7ba3f757fe2402. Backup непосредственно перед включением правил: `.homenet-backup-3793937861.yaml`. Для возврата только правил ИИ: `/opt/bin/python3 /opt/etc/mihomo/recovery-NPM-119-vless-20261109/route.py rollback`. Он сохраняет остальные текущие изменения. Полное восстановление — через HomeNet с исходным конфигом. Watchdog успешно подтверждён, автоматического отката не было. Выбор сохраняется через profile.store-selected.
