# Перенос HomeNet VPN на второй такой же роутер

Архив приватный: в нём подписки, настройки OLCRTC и его приватный SSH-ключ,
клиентские файлы `/opt/root/.ssh`. Tailscale, его состояния и узел TS-LOGNEX
исключены. Не публикуйте архив. SSH host keys роутера не заменяются;
`authorized_keys` объединяется с ключами целевого роутера.

Это автономный перенос установленных версий с исходного роутера, включая
исправленный Mihomo и текущий установленный XKeen, а не загрузка публичного
релиза из интернета. Версии и хэши есть в MANIFEST.json и meta/source.json.
Содержимое исходного роутера не изменяется. Новый роутер должен иметь рабочий
Entware `/opt` на накопителе и SSH с root. Прошивка, LAN, Wi-Fi, системные
пользователи, пароль администратора и подключения провайдера не копируются.
Не восстанавливайте startup-config исходного роутера.

## До установки: веб-интерфейс самого роутера

1. Подключитесь к LAN второго роутера. При одинаковом адресе 192.168.1.1
   временно отключите от компьютера сеть исходного роутера, чтобы не перепутать.
2. В штатном веб-интерфейсе сохраните резервную копию системной конфигурации.
3. Проверьте интернет-подключение, дату/время и доступ к локальному SSH Entware.
   Установка пакетов из интернета не нужна.
4. Если нужна выборочная маршрутизация: создайте политику с точным именем
   `xkeen` в приоритетах подключений и назначьте нужным клиентам эту политику.
   При отсутствии этой политики XKeen может обрабатывать всех клиентов.
   Политики/назначения исходного роутера не переносятся.

## Копирование с Windows через SSH

В PowerShell замените адрес и имя файла на выданные вместе с архивом.
Порт 222 — типичный порт Entware на исходном роутере; если на втором иной,
используйте его. `-O` нужен при отсутствии SFTP.

```powershell
$Router = '192.168.1.1'
$SshPort = 222
$Archive = 'P:\homenet\nginx-proxy-manager\.local\NPM-108\ИМЯ.private.tar.gz'
Get-FileHash -Algorithm SHA256 -LiteralPath $Archive
scp -O -P $SshPort $Archive "root@${Router}:/opt/var/tmp/"
ssh -p $SshPort "root@$Router"
```

Если `/opt/var/tmp` отсутствует, сначала создайте его через SSH:
`mkdir -p /opt/var/tmp`. Сверьте SHA256 с выданной контрольной суммой:

```sh
cd /opt/var/tmp
sha256sum ИМЯ.private.tar.gz
tar -xzf ИМЯ.private.tar.gz
cd homenet-vpn-transfer
sh install.sh --check
sh install.sh --apply
```

`--check` проверяет файлы, архитектуру, свободное место, порты и запрет установки
на исходный роутер. IP берётся с br0. Если определился неверно, передайте
`--lan-ip 192.168.1.1` **обеим** командам. При занятом порте UI можно указать
`--ui-port 63413`. Перед заменой установщик сохраняет старые файлы, останавливает
старые службы Mihomo/XKeen/Zashboard, заменяет их и проверяет конфигурацию.
Известные каталоги Zashboard убираются из рабочей установки в резервную копию,
`external-ui` из Mihomo удаляется. Произвольные сайты веб-сервера не удаляются.
Установщик не удаляет opkg-пакеты и системные библиотеки; зависимости включены
в отдельный runtime. Обновлённый XKeen — копия текущих установленных скриптов
донора, запись о версии в opkg на втором роутере не меняется.

Если Mihomo запущен вручную и не имеет службы, установщик остановится:
остановите его своим обычным способом, затем повторите. Не завершайте
вслепую процессы SSH/Entware. Во время переключения VPN временно прервётся.
При ошибке после начала замены установщик пытается восстановить резервную копию;
если откат не удался, сохраните сообщение и путь к backup.

## Настройка HomeNet через браузер

1. Откройте **точный HTTPS-адрес**, напечатанный установщиком:
   обычно `https://192.168.1.1:63412/`.
2. Примите локальный самоподписанный сертификат этого роутера. Сертификат,
   секрет контроллера Mihomo и секрет шлюза генерируются заново на целевом
   устройстве. Контроллер Mihomo доступен только локально, через HomeNet.
3. Перейдите на `https://192.168.1.1:63412/_gate/login`.
   Шлюз автоматически перенаправит на локальную форму входа.
   Это штатный локальный вход HomeNet: введите пароль **admin второго роутера**.
   Общий сервер Account не требуется. Сессия локального входа — 15 минут.
   Для этого штатный HTTP-интерфейс роутера должен отвечать на loopback:80;
   если порт иной, измените router_url в `/opt/etc/homenet/offline/gateway.json`
   и выполните `/opt/etc/init.d/S99homenet-offline restart`.
4. Откройте интеграцию VPN: проверьте ядро, провайдеры подписок и маршруты.
   Уже скачанные провайдеры и правила включены — старт не зависит от SubLab.
   Автообновление SubLab выключено до проверки доступности его адреса из новой
   сети. Не удаляйте импортированные подписки для первого подключения.
5. Проверьте доступ в интернет с клиента, назначенного политике xkeen.
   Затем проверьте адрес сервиса подписок в интерфейсе VPN, при необходимости
   замените локальный адрес на доступный и включите обновления.
6. OLCRTC и его ключ сохранены: новый роутер использует те же серверы и права
   доступа. Проверьте их доступность с новой сети в разделе OLCRTC.
   Tailscale в конфигурации отсутствует; функциональность самого ядра сохранена.

Локальный вход использует существующий проверяющий пароль шлюз HomeNet;
HTTPS-обёртка нужна для безопасных cookie на IP-адресе. Account, DMS, другие
интеграции и обратный прокси исходной сети не переносятся. Обновление HomeNet
пакетами через DMS в этой автономной установке не настроено.

## Проверка по SSH и откат

```sh
/opt/sbin/mihomo -v
/opt/etc/init.d/S05xkeen status
HOMENET_RUNTIME=/opt/share/homenet/offline-runtime \
  /opt/share/homenet/offline-runtime/bin/curl -fsS http://127.0.0.1:18490/health/ready
```

Проверьте повторный запуск после перезагрузки, когда интернет уже работает.
Служба HomeNet: `/opt/etc/init.d/S99homenet-offline restart`.
Приватные логи: `/opt/var/log/homenet-offline-*.log`,
`/opt/etc/homenet/core/logs/vpn.log`, `BACKUP/install.log`.

Установщик печатает **точный** путь резервной копии. Для отката из каталога
распакованного архива:

```sh
sh install.sh --rollback /opt/var/backups/homenet-transfer-ДАТА-ВРЕМЯ-СУФФИКС
```

Возвращаются старые файлы Mihomo/XKeen/Zashboard и SSH, а также DNS-правила
установщика; старые службы запускаются снова. Системная конфигурация прошивки
не меняется установщиком. Не удаляйте backup и распакованный архив до проверки
работы и перезагрузки. При успешном переносе храните приватный архив и резервные
копии в защищённом месте.

Установка на настоящий второй роутер автоматически не выполнялась. Локальные
проверки и проверка ARM64-зависимостей не заменяют проверку его сети/политик.

## Подготовка отключённой флешки на компьютере

Для переноса без запуска установщика на роутере сначала снимите полный образ
носителя. Работайте с его копией; проверьте ext4 через e2fsck до установки и
после размонтирования. Подготовка запускается в Linux от root, где раздел
Entware смонтирован именно в `ROOT/opt`:

```sh
python3 scripts/offline-router/install.py --prepare-offline ROOT \
  --bundle /path/to/extracted/homenet-vpn-transfer --lan-ip 192.168.2.1
```

Команда отказывается работать с `/` и проверяет ARM64 по старому ядру. Она
сохраняет старые файлы, объединяет SSH authorized_keys, отключает старые
XKeen UI/Net и nginx-manager-lite, убирает активный nginx-сайт Zashboard.
Службы на компьютере не запускаются. Выполните отдельно генерацию сертификата
из подготовленного front через ARM64-эмулятор с IP 192.168.2.1 и путями
`ROOT/opt/etc/homenet/offline/{cert,key}.pem`.

При первом включении S04homenet-clock поднимает отставшие часы до времени
подготовки; правильные часы не меняются, последующей синхронизацией управляет
штатный NTP роутера. Сохранённые правила XKeen с policy marks исходного роутера
удаляются: S05xkeen создаёт свои hook и schedule из политик целевого устройства.
В этих генерируемых скриптах сохраняется PATH с приватными утилитами.

После записи проверенного образа на носитель подключите его к выключенному
второму роутеру, включите и подождите примерно минуту. Установку через SSH
повторять не нужно. Вход: `https://192.168.2.1:63412/_gate/login`, пароль admin
второго роутера. Проверка реального VPN-трафика и политик требует этого роутера.

`usb_image.py` — Windows-помощник резервного копирования и записи изменённых
блоков. Ему нужны явно записанные Number/SerialNumber/UniqueId/Size USB-диска,
границы раздела Entware, before.img, after.img и ready.json с хэшами блоков.
Он запрещает изменения GPT/других разделов, проверяет исходные байты перед
записью, блокирует нужный RAW-том и перечитывает записанные блоки. При ошибке
пытается вернуть затронутые блоки из before.img. Оба образа храните приватно.
